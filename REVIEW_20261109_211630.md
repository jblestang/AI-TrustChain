## 1. Network Architecture & Late-Joining Receiver Resilience

| ID | Severity | Finding | Status / Resolution |
| :--- | :--- | :--- | :--- |
| **NET-01** | High | Previously, `EgressIps` initialized `expected_frame_seq: 0` and `last_chain_hash: [0; 32]`. If the Egress IPS booted up after the Ingress IPS was already running (or reconnected after downtime), the very first received Control Frame (`frame_seq > 0`) caused a false-positive `ControlStreamGap` alert. | **Resolved**: Changed `expected_frame_seq` to `Option<u64>` (`None` initially). `EgressIps` now dynamically anchors its hash chain and sequence counter on the first AEAD-authenticated Control Frame it receives, and provides [`EgressIps::reset_sync_state`](file:///Users/jean-baptiste/AI-TrustChain/src/egress_ips.rs#L118-L122) for planned reconnections. |
| **NET-02** | High | Previously, `FlowEpochSummary` only carried `cumulative_pdu_count` since Ingress boot. If a flow was active *before* Egress came online (`cumulative_pdu_count > 0`) and then went quiet right as Egress joined (`epoch_pdu_count == 0`), Egress falsely raised `FlowDeleted`. | **Resolved**: Added `epoch_pdu_count` to [`FlowEpochSummary`](file:///Users/jean-baptiste/AI-TrustChain/src/model.rs#L132-L147) and `baseline_cumulative_pdus` / `expected_pdus_since_sync` to `EgressFlowState`. `EgressIps` now evaluates `FlowDeleted` strictly against PDUs expected *since Egress synchronized*. |
| **NET-03** | Medium | If no receiver is present or epoch flushes are delayed, `IngressIps` must never block or leak memory from historical flows. | **Resolved**: Added [`IngressConfig`](file:///Users/jean-baptiste/AI-TrustChain/src/ingress_ips.rs#L27-L44) with a per-flow ring buffer (`max_pending_entries_per_flow`) and automatic idle-flow eviction (`flow_idle_timeout_us`). |
