## 1. Zero-False-Positive Audit & Fixes

| ID | Domain | Potential False Positive Scenario | Resolution Implemented |
| :--- | :--- | :--- | :--- |
| **ZFP-01** | Remote Egress (Clock Domain) | When a sensor's clock lags the IPS wall clock (e.g., by hours) and a **brand-new flow** starts from that sensor, if the first data packet beats its control frame to Egress, `state.sensor_to_ips_clock_offset_us` is still `None` for that new flow. Comparing raw `first_data_seen_us` against `current_time_us` would immediately trigger a false `FlowAdded` alert before `control_skew_tolerance_us` actually elapsed. | **Resolved**: Added `global_clock_offset_us: Option<i64>` to [`EgressIps`](file:///Users/jean-baptiste/AI-TrustChain/src/egress_ips.rs#L139-L143) and normalized `first_data_seen_us` in [`evaluate_single_flow`](file:///Users/jean-baptiste/AI-TrustChain/src/egress_ips.rs#L455-L473) so newly arriving flows inherit the sensor-to-IPS clock offset immediately. |
| **ZFP-02** | Remote Egress & PCAP (Transport) | Benign L2/L3 packet duplication or TCP retransmission on a lossy link delivers a second copy of an already-verified PDU, which would otherwise fail to find an unconsumed slot in `pending_ingress` and raise a false `PduAdded` alert. | **Resolved**: Added `recent_verified_pdus: VecDeque<(u64, u128)>` and [`VerifierConfig::absorb_network_retransmissions`](file:///Users/jean-baptiste/AI-TrustChain/src/egress_ips.rs#L44-L48) in [`src/egress_ips.rs`](file:///Users/jean-baptiste/AI-TrustChain/src/egress_ips.rs#L345-L351) to absorb duplicate deliveries of already-verified `(timestamp_us, xyi_mac)` PDUs. |
| **ZFP-03** | Storage VM Live PCAP Verification | During `verify_pcap_against_live_store` while the algorithm is actively running, the `.pcap` file may contain brand-new packets on a known flow whose control epoch is still open in memory on the Ingress IPS VM (not yet sent to the Storage VM). Additionally, different flows may have different earliest/latest retained timestamps across rotated segments. | **Resolved**: [`verify_packets_with_frames`](file:///Users/jean-baptiste/AI-TrustChain/src/pcap_verifier.rs#L430-L526) tracks per-flow `flow_min_ts` and `flow_max_ts` across the retained segments and, in live mode (`is_live_mode == true`), excludes both rotated-out prefix PDUs (`< f_min`) and in-flight un-flushed tail PDUs (`> f_max + control_skew_tolerance_us`) on known flows while still evaluating 100% of unknown flows (`FlowAdded`). |
