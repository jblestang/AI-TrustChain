## 1. Cybersecurity & Cryptographic Review

| ID | Severity | Finding | Status / Resolution |
| :--- | :--- | :--- | :--- |
| **CYB-01** | Medium | `TrustChainKeys` previously derived `#[derive(Debug)]`, which could accidentally leak raw 256-bit subkeys into logs if formatted, and did not scrub key material on drop. | **Resolved**: Replaced `#[derive(Debug)]` with a custom `Debug` implementation that outputs `[REDACTED]` and added `#[derive(ZeroizeOnDrop)]` from `zeroize`. |
| **CYB-02** | Info | Domain separation between the per-PDU MAC key and the Control Stream AEAD key is enforced via `blake3::derive_key` with distinct context strings. | **Verified**: Prevents any cross-protocol key reuse between `BLAKE3` keyed hashing and `ChaCha20-Poly1305`. |
| **CYB-03** | Info | Control stream anti-replay and anti-truncation: `EncryptedControlFrame` binds `(sender_id, frame_seq)` into both the 96-bit AEAD nonce and the Additional Associated Data (AAD) with magic header `0x5443`, while chaining payloads via `prev_chain_hash`. | **Verified**: Tested in `test_data_arriving_before_control_frame_and_control_stream_tampering`. |
| **CYB-04** | Future Note | If `bincode::deserialize` is exposed to untrusted raw sockets before AEAD verification, length prefixes can cause large allocations. Here, `bincode::deserialize` is only invoked **after** `ChaCha20-Poly1305` authentication succeeds (`decrypt_control_frame`), preventing unauthenticated allocation DoS. | **Verified Safe**. |

## 2. Radar / Sensor Signal Processing & Network Flow Review

| ID | Severity | Finding | Status / Resolution |
| :--- | :--- | :--- | :--- |
| **SIG-01** | Info | Floating-point representation drift (`-0.0` vs `+0.0` or non-canonical `NaN` payloads) on `[X, Y, I]` coordinates across heterogeneous processors could cause false-positive `PduAltered` alerts. | **Verified**: `canonicalize_f64` in [`src/crypto.rs`](file:///Users/jean-baptiste/AI-TrustChain/src/crypto.rs) normalizes `-0.0` to `+0.0` and canonicalizes `NaN` bit patterns before hashing. |
| **SIG-02** | Info | Multi-PDU framing over TCP is subject to TCP Segmentation Offload (TSO), Generic Receive Offload (GRO), and middlebox re-framing. | **Verified**: Both [`IngressIps`](file:///Users/jean-baptiste/AI-TrustChain/src/ingress_ips.rs) and [`EgressIps`](file:///Users/jean-baptiste/AI-TrustChain/src/egress_ips.rs) operate at the individual PDU level (`PduControlEntry`), making verification invariant to packet coalescing or splitting. |
| **SIG-03** | Info | Out-of-order race condition when the cleartext UDP/TCP packet arrives at Egress IPS slightly before the out-of-band Control Frame. | **Verified**: `pending_egress` buffers early data PDUs up to `control_skew_tolerance_us` (default 50 ms) and reconciles them as soon as the Control Frame arrives. |
