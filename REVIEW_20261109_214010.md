## 1. Concurrency & Filesystem Race-Condition Review

| ID | Severity | Finding | Status / Resolution |
| :--- | :--- | :--- | :--- |
| **CONC-01** | High | Calling `read_and_heal_segment` (which opens segments in read-write mode and calls `set_len`) while the writer thread is actively appending a record to the tail of the latest segment could race with an in-flight write and truncate bytes the writer is currently writing. | **Resolved**: Added [`RotatingControlStore::read_all_frames_live`](file:///Users/jean-baptiste/AI-TrustChain/src/storage.rs#L211-L237) and `read_segment_readonly` which open files strictly in read-only mode (`File::open`) and never call `set_len`. Any in-flight partial tail record simply terminates the reader loop at the last complete checksummed frame without touching the file on disk. |
| **CONC-02** | High | While the live PCAP verifier is iterating over `list_segments`, the active `RotatingControlStore` writer may rotate to a new segment and unlink (`fs::remove_file`) the oldest segment file, causing `File::open` to return `ErrorKind::NotFound`, or may have just created a new segment file whose 8-byte magic header is still in flight. | **Resolved**: `read_all_frames_live` explicitly catches `ErrorKind::NotFound` and `InvalidSegmentMagic` on concurrent segments, skipping evicted/in-flight segments cleanly and sorting/deduplicating by `frame_seq`. |
