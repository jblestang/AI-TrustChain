# Full Design Weakness Review — AI-TrustChain
**Timestamp**: `2026-11-09T21:58:00+01:00`

See the full analysis of all 8 identified design weaknesses (3 Critical, 3 High, 2 Medium):

1. **DW-01 [CRITICAL — CRYPTO]**: `ChaCha20-Poly1305` AEAD Nonce Reuse across Ingress power cycles (`sender_id || frame_seq` resets to 0 on reboot unless a unique session/boot nonce or persisted sequence recovery is used).
2. **DW-02 [CRITICAL — DoS / MEMORY]**: `EgressIps` has unbounded flow tables and continues buffering into `pending_egress` even after `flow_added_alerted = true`.
3. **DW-03 [CRITICAL — PCAP VERIFIER]**: `verify_packets_with_frames` filters all `.pcap` PDUs by `[min_retained_ts_us, max_retained_emitted_us]`, allowing an attacker to evade `PduAdded` and `FlowAdded` detection in `.pcap` audits simply by setting a forged timestamp outside the window.
4. **DW-04 [HIGH — TIMING BYPASS]**: An attacker injecting a PDU with `timestamp_us = u64::MAX` causes `current_time_us.saturating_sub(pdu.timestamp_us)` to evaluate to `0 < control_skew_tolerance_us` forever, permanently evading `PduAdded` and `FlowAdded` alerts.
5. **DW-05 [HIGH — DETECTION ACCURACY]**: Matching `PduAltered` strictly on exact `timestamp_us` equality fails if the attacker also alters the timestamp slightly or if multiple PDUs in a burst share the same timestamp.
6. **DW-06 [HIGH — STATE SYNC]**: `IngressIps` ring-buffer eviction (`max_pending_entries_per_flow`) increments `cumulative_pdu_count` for evicted entries, causing Egress to flag those legitimate packets as `PduAdded`.
7. **DW-07 [MEDIUM — CONTROL REPLAY]**: `EgressIps::receive_control_frame` accepts replayed older control frames (`frame_seq < expected_frame_seq`), rolling back its sequence number and hash chain state.
8. **DW-08 [MEDIUM — STORAGE INVARIANT]**: If `write_all` fails mid-record on disk-full (`ENOSPC`), `active_file` offset is not rolled back to `active_file_len`.
